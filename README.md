# نمونه‌کده | گالری نمونه‌کارهای فرانت‌اند فارسی

این مخزن یک وب‌سایت گالری است که **۱۱ وب‌سایت مستقل و کامل** را معرفی می‌کند. هر کارت در گالری
شما را به یک سایت واقعی با طراحی، محتوا، تصاویر و تعامل‌های خودش می‌برد — مجموعه‌ای از
اسکرین‌شات نیست.

همه‌ی رابط‌ها فارسی و راست‌به‌چپ‌اند و در رابط عمومی، هیچ پیوند یا آیکون گیت‌هاب وجود ندارد.

## فناوری‌ها

| بخش | ابزار |
| --- | --- |
| گالری اصلی | React 18 + TypeScript + Vite 5 |
| دموها | HTML + CSS + JavaScript (بدون فریم‌ورک، بدون وابستگی) |
| فونت | Vazirmatn (متغیر، woff2) — در گالری از طریق پکیج npm، در هر دمو به‌صورت فایل محلی |
| تصاویر | فایل‌های محلی WebP داخل مخزن |
| هاست | Cloudflare Workers Static Assets یا Cloudflare Pages (اتصال به گیت‌هاب) |

## ساختار پوشه‌ها

```
.
├── index.html                  # صفحه‌ی گالری (lang=fa dir=rtl)
├── src/
│   ├── App.tsx
│   ├── data/projects.ts        # ★ ثبت متمرکز پروژه‌ها
│   ├── lib/fa.ts               # یکسان‌سازی متن فارسی برای جست‌وجو
│   ├── components/             # هدر، هیرو، گالری، کارت، حالت خالی، درباره، فوتر
│   └── styles/gallery.css
├── public/                     # هرچه اینجا باشد عیناً به dist کپی می‌شود
│   ├── favicon.svg
│   ├── 404.html                # صفحه‌ی ۴۰۴ فارسی Cloudflare Pages
│   ├── images/previews/        # تصویر پیش‌نمایش هر دمو (۱۲۰۰×۸۰۰ WebP)
│   └── demos/
│       ├── fashion/            # آینه — خانه‌ی مد و استایل
│       ├── sports/             # پیکان — باشگاه ورزشی و تناسب اندام
│       ├── cars/               # ماشین‌نما — نمایشگاه خودرو
│       └── store/              # لوازم — فروشگاه سبک زندگی
└── scripts/
    ├── postbuild.mjs           # بررسی خروجی build (بخشی از npm run build)
    ├── check-site.mjs          # دروازه‌ی یکپارچگی: rtl/fa، تصاویر، پیوندها، attribution
    ├── fetch-images.mjs        # دانلود تصاویر از Wikimedia Commons
    ├── sync-images.mjs         # ساخت دوباره‌ی پیش‌نمایش‌ها از تصویر hero هر دمو
    ├── image-manifest.mjs      # فهرست تصویرهای پروژه (منبع + مقصد)
    └── lib/commons.mjs         # کلاینت ساده‌ی API مشترک
```

## فرمان‌ها

| فرمان | کار |
| --- | --- |
| `npm run dev` | گالری و دموها روی `http://localhost:5173` |

| `npm run preview` | سرو کردن `dist` روی `http://localhost:4173` |
| `npm run typecheck` | فقط بررسی تایپ‌ها |

| `npm run sync:images` | تولید دوباره‌ی `public/images/previews/*.webp` از hero هر دمو |
| `npm run search:images` | جست‌وجوی گزینه‌های تصویر در Commons |
| `npm run fetch:images` | دانلود و ساخت تصویرهای منیفست |

مستقیم در مرورگر باز کرد.

## بیلد و پیش‌نمایش خروجی

```bash
npm run build      # tsc --noEmit && vite build && بررسی ساختار
npm run preview    # serving dist روی http://localhost:4173
```

خروجی:

```
dist/
├── index.html
├── assets/
├── images/previews/*.webp
└── demos/{fashion,sports,cars,store}/index.html + assets/
```

اسکریپت `scripts/postbuild.mjs` بعد از هر build این‌ها را کنترل می‌کند: وجود `index.html` هر چهار
دمو، `lang="fa"` و `dir="rtl"` در آن‌ها، نبود پیوند گیت‌هاب، نبود نشانی تصویر بیرونی، و وجود
تصویرهای پیش‌نمایش. اگر موردی نباشد، build با موفقیت تمام می‌شود؛ در غیر این صورت با کد خطا
خارج می‌شود.

## جست‌وجوی فارسی

جست‌وجو در `src/lib/fa.ts` یکسان‌سازی می‌کند و بعد تطبیق می‌دهد:

- `ي` عربی ⇄ `ی` فارسی، `ك` ⇄ `ک`، `ى` ⇄ `ی`، `ة` ⇄ `ه`
- حذف نیم‌فاصله (`U+200C`)، تطویل (`U+0640`) و اعراب
- یکسان‌سازی فاصله‌های یونیکد (از جمله NBSP) و حذف فاصله‌های اضافه
- ارقام فارسی/عربی ⇄ لاتین، و حروف لاتین به حروف کوچک

جست‌وجوی چندکلمه‌ای AND است (همه‌ی واژه‌ها باید پیدا شوند، بدون وابستگی به ترتیب) و روی
عنوان، توضیح، دسته‌بندی، واژه‌های کلیدی، امکانات و فناوری‌های هر پروژه اعمال می‌شود. فیلتر
دسته‌بندی و جست‌وجو با هم کار می‌کنند. متن اصلی دست‌نخورده نمایش داده می‌شود.

## افزودن دمو تازه

۱. پوشه بسازید: `public/demos/<id>/` و داخل آن `index.html`، `styles.css`، `app.js` و
   `assets/` (تصاویر، فونت و …). مسیرهای تصویر را نسبی بنویسید (`./assets/img/x.webp`) تا در
   مسیر تودرتو `/demos/<id>/` درست کار کند.
۲. تصویر پیش‌نمایش گالری را با ابعاد ۱۲۰۰×۸۰۰ در `public/images/previews/<id>.webp` بگذارید.
۳. یک عضو به آرایه‌ی `projects` در `src/data/projects.ts` اضافه کنید (همان `id`، عنوان،
   توضیح، `category`، `preview`، `url: '/demos/<id>/'`، `technologies`، `keywords`،
   `highlights`، `accent`). فهرست دسته‌بندی‌ها خودکار از همین داده ساخته می‌شود.
۴. `npm run build` را اجرا کنید تا بررسی‌های ساختاری هم اجرا شوند.
۵. Push کنید؛ Cloudflare با اتصال گیت‌هاب خودش دوباره deploy می‌کند.

کامپوننت‌های گالری داده‌محورند؛ برای دمو جدید نیازی به بازنویسی `App.tsx` یا کارت‌ها نیست.

نمای موبایل گالری نوار دسترسی پایین و فیلترهای افقی دارد. اصلاحات مشترک دموها در
`public/demos/shared/mobile.css` و `mobile.js` نگه‌داری می‌شوند؛ هنگام انتقال یک دمو، پوشه‌ی
`shared` را هم کنار پوشه‌ی آن قرار دهید. منوهای موبایل با لمس بیرون، Escape و تغییر به عرض
دسکتاپ بسته می‌شوند. پنجره‌های محصول و خودرو دکمه‌ی بستن ثابت هنگام اسکرول دارند.

همه‌ی دموها یک نوار ثابت «بازگشت به صفحه اصلی» دارند که به `/#demos` می‌رود؛ حتی با ورود
مستقیم به دمو و بدون جاوااسکریپت هم قابل استفاده است. استایل آن در
`public/demos/shared/navigation.css` است. برای دموی جدید، لینک این استایل و `nav.demo-return`
را از یکی از دموها کپی کنید. بررسی پس از build نبودن این مسیر بازگشت را خطا می‌گیرد.

### پیش‌نمایش گرافیکی و حرکت گالری

پیش‌نمایش‌های گالری ترکیب‌های گرافیکی اختصاصی از متن، رنگ و تصاویر همان دمو هستند. برای بازسازی آن‌ها `npm run generate:previews` را اجرا کنید؛ ثبت منابع مشتق‌شده در `public/images/previews/ATTRIBUTION.json` حفظ می‌شود. تنظیمات `visual` هر پروژه شامل رنگ سطح، متن، رنگ ثانویه، مسیر تصویر و نوع چیدمان است. برای خروجی یکسان، فونت Vazirmatn باید در سیستم سازنده نصب باشد.

بازشدن و بسته‌شدن پروژه‌ها از موقعیت اسکرول مشتق می‌شود. بالا/چپ به عقب و پایین/راست به جلو می‌رود؛ کلیک یا Enter پروژه را به نقطهٔ نمایش کامل می‌برد. Escape یا بازگشت، وضعیت قبل از ورود با کلیک را بازیابی می‌کند. نمای پروژه اسکرول صفحه را قفل نمی‌کند؛ قفل فقط متعلق به پنجره‌های اطلاعاتی است.

## استفاده از بیلد استاتیک React/Vue در یک دمو

هر دمو فقط یک پوشه‌ی ایستا در `public/demos/<id>/` است؛ می‌توانید خروجی بیلد یک فریم‌ورک دیگر
را آنجا بگذارید:

```bash
cd ../my-vue-demo
npm run build -- --base=./          # یا در vite.config: base: './'
rm -rf ../demo/public/demos/my-vue-demo/assets
cp -r dist/* ../demo/public/demos/my-vue-demo/
```

نکته‌ها: مسیر assetها باید نسبی باشد (`base: './'`)، فایل `index.html` بیلد‌شده جای فایل
دستی را می‌گیرد، و اگر از React Router استفاده می‌کنید `HashRouter` بگیرید یا یک `_redirects`
اختصاصی برای همان دمو اضافه کنید تا مسیر دمو با روت گالری جایگزین نشود.

## تصاویر و اعتبار منبع

- همه‌ی تصویرها فایل‌های محلی داخل مخزن‌اند: `public/demos/<id>/assets/img/*.webp` برای دموها و
  `public/images/previews/*.webp` برای پیش‌نمایش گالری. بعد از deploy هیچ درخواستی به سرور
  تصویر بیرونی زده نمی‌شود.
- منبع تصویرها **Wikimedia Commons** است (لایسنس‌های CC0 / CC BY / CC BY-SA / مالکیت عمومی).
  برای هر تصویر، عنوان فایل، نام اثر‌گر و لایسنس در `public/demos/<id>/assets/ATTRIBUTION.json`
  ثبت شده و فهرست کامل با منبع در `public/images/ATTRIBUTION.json` جمع بسته می‌شود.
- چرا Unsplash/Pexels؟ این‌ها منبع ترجیحی طرح اولیه بودند، ولی شبکه‌ی این ماشین فقط به
  `upload.wikimedia.org`، `commons.wikimedia.org`، `registry.npmjs.org` و چند میزبان محدود پاسخ
  می‌دهد؛ `images.unsplash.com`، `images.pexels.com`، `cdn.pixabay.com` و `picsum.photos` مسدودند.
  برای همین همه‌ی تصویرها از Commons گرفته شده‌اند و **تک‌تک آن‌ها با چشم بررسی شده‌اند** تا سوژه‌ی
  هر کارت با تصویر همان کارت یکی باشد.

ابزار دانلود:

```bash
node scripts/fetch-images.mjs search "چراغ مطالعه"      # گزینه‌یابی
node scripts/fetch-images.mjs build                     # دانلود طبق image-manifest.mjs
```

اسکریپت با `sharp` تصویر را resize می‌کند، به WebP با کیفیت ۸۰ تبدیل می‌کند، فرمت خروجی را
اعتبارسنجی می‌کند و اطلاعات لایسنس را در فایل attribution می‌نویسد.

## استقرار روی Cloudflare Workers

برای پروژه‌ی Worker با نام `demo`، تنظیمات ساخت متصل به گیت‌هاب:

- **Build command:** `npm run build`
- **Deploy command:** `npx wrangler deploy --assets ./dist`
- **Root directory:** ریشه‌ی مخزن

فایل `wrangler.jsonc` نام Worker را `demo`، تاریخ سازگاری را `2026-10-12` و پوشه‌ی
فایل‌های ایستا را `./dist` تعیین می‌کند. نام Worker در داشبورد باید با `name` در این فایل
یکی باشد. `not_found_handling: "404-page"` صفحه‌ی `dist/404.html` را برای مسیرهای ناموجود
نمایش می‌دهد و هر دمو از `dist/demos/<id>/index.html` سرو می‌شود.

برای بررسی تنظیمات استقرار بدون انتشار:

```bash
npm run build
npx wrangler deploy --assets ./dist --dry-run
```

خطای `A compatibility_date is required` با همین فایل تنظیمات برطرف می‌شود؛ فرمان deploy
فعلی نیازی به تغییر ندارد.

## استقرار روی Cloudflare Pages (گزینه‌ی دیگر)

1. مخزن را به Cloudflare Pages وصل کنید (**Workers & Pages → Create → Pages → Connect to Git**).
2. تنظیمات پروژه:

| تنظیم | مقدار |
| --- | --- |
| Framework preset | `None` (یا Vite) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | `/` (ریشه‌ی مخزن) |
| Node.js version (Environment variables) | `NODE_VERSION = 20` |

3. Deploy را بزنید. چون دموها فایل‌های واقعی داخل `dist/demos/<id>/index.html` هستند، نشانی‌های
   `/demos/fashion/`، `/demos/sports/`، `/demos/cars/` و `/demos/store/` بدون هیچ قانون rewrite
   باز می‌شوند. **عمداً هیچ `_redirects` سراسری مثل `/* /index.html 200` اضافه نکنید**؛ آن مسیر
   دموها را با گالری جایگزین می‌کند. صفحه‌ی `public/404.html` برای مسیرهای اشتباه کافی است.
4. برای اطمینان از کش صحیح assetها می‌توانید `public/_headers` را اضافه کنید (اختیاری):

```
/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

هاست رایگان Pages برای این سایت کافی است (سایت کاملاً ایستا، بدون backend، دیتابیس یا API key).

## قراردادهای داخل دموها

- **قاعده‌ی `[hidden]`:** هر `styles.css` درست بعد از `box-sizing` این خط را دارد:
  `[hidden]{display:none !important}`. بدون آن، `display:flex` روی درایور سبد، مودال یا دکمه‌ی
  پاک‌کردن جست‌وجو، قواعد مرورگر را می‌پوشاند و المان از همان بار اول صفحه دیده می‌شود.
- **لحن متن‌ها:** بازدیدکننده در نقش مشتری است، نه توسعه‌دهنده. پس متن‌ها به «شما» خطاب
  می‌کنند، توضیح معماری نمی‌دهند و تنها یک بار — کنار فرم یا سبد — صریحاً می‌گویند صفحه
  نمونه‌ی نمایشی است. واژه‌های فنی فقط در `keywords` بی‌نمایش `projects.ts` می‌آیند.
- **آمار با محتوا یکی باشد:** شمارنده‌های هیرو و بخش «پیکان در یک نگاه» باید با تعداد واقعی
  کارت‌ها بخواند (باشگاه ۶ رشته، نمایشگاه ۱۰ خودرو). عدد قلابی سریع‌ترین راه بی‌اعتمادی است.
- **تصویر = همان سوژه:** تصویر هر کارت/محصول باید موضوع همان کارت باشد؛ این با چشم بررسی
  می‌شود، نه با اندازه‌ی فایل.

## آنچه عملاً بررسی شد

هر مورد در مرورگر واقعی (دسکتاپ ۱۴۴۰ و موبایل ۳۹۰) آزمایش شده است:

- گالری: جست‌وجو با یکسان‌سازی (`ي/ی`، `ك/ک`، `ى`، اعراب، تطویل، نیم‌فاصله، ارقام فارسی/عربی،
  NBSP)، جست‌وجوی چندواژه‌ای بدون وابستگی به ترتیب، کار هم‌زمان فیلتر دسته و جست‌وجو، حالت خالی
  و دکمه‌ی بازگشت آن، منوی موبایل، نبود سرریز افقی.
- مد: فیلتر فصل، لایت‌باکس (کلیک، پیکان‌ها، Esc، `alt` معنادار)، فرم عضویت و پیام‌های خطا.
- باشگاه: فیلتر رشته‌ها، تب‌های روز هفته، دکمه‌ی اطلاع‌رسانی، فرم ثبت‌نام (اعتبارسنجی و موفق).
- خودرو: جست‌وجو + فیلتر کلاس + مرتب‌سازی با هم، پنجره‌ی جزئیات و تعویض تصویر، سقف سه‌تایی
  مقایسه و جدول مقایسه، فرم مشاوره.
- فروشگاه: سبد با `localStorage`، حذف/تغییر تعداد، تسویه‌حساب با اعتبارسنجی کد پستی، جست‌وجو،
  فیلتر دسته، مرتب‌سازی، نمای سریع، درایور سبد و Esc.
- همه‌ی صفحه‌ها: `lang="fa" dir="rtl"`، فونت‌های محلی، نبود هر پیوند یا آیکون گیت‌هاب،
  نبود تصویر بیرونی، نبود خطای کنسول.

`npm run check:site` هم همین موارد ساختاری را در هر build دوباره کنترل می‌کند.

| فایل تصویر HTML یا ۰ بایت است | دانلود شکسته؛ `node scripts/fetch-images.mjs build` دوباره اجرا کنید و اندازه/فرمت را با `sharp metadata` بررسی کنید. |
| فونت فارسی نمی‌آید | فایل woff2 در `assets/fonts` باشد و `@font-face` مسیر نسبی درست داشته باشد. |
| چیدمان روی موبایل افقی اسکرول می‌کند | `overflow-x: clip` روی body و بررسی عرض جدول مقایسه/کارت‌ها؛ از `min-width` بزرگ روی المان‌های داخل flex استفاده نکنید. |
| جست‌وجوی فارسی نتیجه نمی‌دهد | املای کلیدواژه را با شکل `ي/ی` و `ك/ک` امتحان کنید؛ یکسان‌سازی در `src/lib/fa.ts` است و روی همه‌ی فیلدها اعمال می‌شود. |
| سبد خرید فروشگاه پاک می‌شود | کلید `localStorage` برابر `lavazem-cart-v1` است؛ در حالت Incognito یا بعد از `Clear site data` مقدار اولیه برمی‌گردد. |
| درایور سبد/مودال از همان اول صفحه باز است | قاعده‌ی `[hidden]{display:none !important}` از آن فایل CSS حذف شده؛ دوباره درست‌اش کنید. |

## مستندات توسعه‌دهنده

این README بخشی از مخزن است، نه بخشی از وب‌سایت عمومی. گالری و دموها هیچ راهنمای
توسعه‌دهنده یا پیوند مخزن به بازدیدکننده نشان نمی‌دهند.


## روبان؛ فروشگاه اکسسوری دخترانه — نمونه‌کار شمارهٔ ۲

دومین نمونه‌کار گالری در مسیر `/demos/roban/` است. دمو شامل ویترین واقعی Three.js، ۱۲ محصول،
جست‌وجوی فارسی، علاقه‌مندی، سبد ذخیره‌شونده و سفارش نمایشی است. نام‌ها و قیمت‌ها فرضی‌اند؛
فرم سفارش اطلاعات شخصی را ذخیره یا ارسال نمی‌کند.

`npm run dev` و `npm run build` ابتدا ماژول صحنه را از `src/demos/roban/scene.ts` می‌سازند.
خروجی `scene.js` تولیدی و نادیده‌گرفته‌شده در Git است؛ برای بازسازی آن حین توسعه `npm run build:scene`
را اجرا کنید. خروجی build شامل همهٔ فایل‌های لازم دمو و فونت‌ها و تصاویر محلی است؛ وابستگی به CDN ندارد.

۱۳ تصویر اختصاصی با ابزار داخلی Imagegen ساخته شده‌اند. دستور کامل هر تصویر در
`public/demos/roban/assets/ATTRIBUTION.json` ثبت شده است. این رکوردها با `origin: generated`
مشخص می‌شوند و نشانی منبع یا لایسنس عکس‌های استوک برای آن‌ها جعل نشده است. ابزار همگام‌سازی
آن‌ها را حفظ می‌کند و وارد فهرست دانلود Commons نمی‌کند. پیش‌نمایش همین دمو را با
`npm run generate:previews -- roban` می‌توان بدون تغییر پیش‌نمایش‌های دیگر بازسازی کرد.

در کاهش حرکت یا نبود WebGL، تصویر ویترین و دکمه‌های محصولات در دسترس می‌مانند. صحنه هنگام
خروج از دید، مخفی‌شدن تب یا بازبودن پنجرهٔ خرید متوقف می‌شود و پس از بازیابی WebGL دوباره آماده می‌شود.

## اُرا — نمونه‌کار شمارهٔ ۵

کلینیک مفهومی پوست و زیبایی اُرا در `/demos/aura/` قرار دارد و عضو پنجم ثبت مرکزی پروژه‌هاست.
نسخهٔ بازطراحی‌شده از مشکی، زرشکی و رنگ‌های مرواریدی، پرترهٔ سینمایی تمام‌صفحه و تایپوگرافی
بزرگ استفاده می‌کند. متن‌ها کوتاه‌تر و مشخصاً دربارهٔ خدمات و مشاوره‌اند.

فونت‌های اُرا با دموهای دیگر متفاوت‌اند: Estedad SemiBold برای تیترها، Shabnam در دو وزن
برای متن و رابط، و Cormorant Garamond برای نشان و نوشته‌های لاتین بزرگ. همهٔ فایل‌ها WOFF2
و محلی‌اند؛ منبع، هش فایل‌ها و متن مجوزها در `public/demos/aura/assets/fonts/` ثبت شده‌اند.
در لینوکس، سازندهٔ پیش‌نمایش این فایل‌ها را با تنظیم موقت Fontconfig به همان فرایند معرفی
می‌کند و فونتی روی سیستم نصب نمی‌کند. در سیستم‌های دیگر، این خانواده‌ها باید در دسترس رندرکننده باشند.

فرم کرومِ تألیفی در `src/demos/aura/hero.ts` با نورپردازی و متریال واقعی Three.js رندر می‌شود و
به حرکت اشاره‌گر و اسکرول واکنش نشان می‌دهد. ذره‌بین تصویر، جزئیات همان عکس را بزرگ می‌کند؛
فرم چهره یا تصویر نتیجهٔ درمان را شبیه‌سازی نمی‌کند. بخش خدمات با هر انتخاب تصویر را عوض
می‌کند و در موبایل تصویر حین مرور خدمات در دید می‌ماند.

اطلس زیبایی از هندسهٔ تألیفی مجسمه در `src/demos/aura/scene.ts` استفاده می‌کند. مجسمه با کشیدن
یا دکمه‌ها می‌چرخد؛ کنترل‌های خدمات روی نقاط تصویرشدهٔ مدل قرار می‌گیرند. نمای «خطوط» شبکهٔ
هندسه را نشان می‌دهد. اسکرول عمودی لمس حفظ می‌شود. هر دو صحنه هنگام خارج‌شدن از دید،
مخفی‌شدن تب یا بازبودن رزرو متوقف می‌شوند؛ کاهش حرکت، رندر پیوسته را خاموش می‌کند.
در نبود WebGL، عکس اصلی، طرح جایگزین و کنترل‌های خدمات باقی می‌مانند.

فرم رزرو به سرور متصل نیست و اطلاعات شخصی درخواست، ذخیره یا ارسال نمی‌کند. روزها با تقویم
شمسی و مرز روزِ تهران محاسبه می‌شوند. انتخاب خدمت، روز و ساعت، مرور، ویرایش و رسید نمایشی
در دسترس‌اند. نمایشی‌بودن رزرو در فرم و رسید مشخص است.

چهار تصویر با ابزار داخلی `image_gen` ساخته و در `public/demos/aura/assets/img/` ذخیره شده‌اند.
دستورهای ساخت در `public/demos/aura/assets/ATTRIBUTION.json` ثبت شده‌اند. پیش‌نمایش تألیفی
گالری با `npm run generate:previews -- aura` بازسازی می‌شود. این پیش‌نمایش اسکرین‌شات مرورگر نیست.
`npm run dev` و `npm run build` فایل تولیدی `public/demos/aura/scene.js` را خودکار می‌سازند.

تست‌ها رزرو، تقویم، ناوبری، همگامی تصاویر خدمات، نماهای مجسمه، تمام رأس‌های هندسه در قاب‌های
مختلف، توقف رندر، کاهش حرکت، بازیابی WebGL و آزادسازی منابع را بررسی می‌کنند. جایگزین GPU
در تست‌ها، کیفیت ظاهری، لمس واقعی، تلهٔ فوکوس مرورگر یا FPS دستگاه را اثبات نمی‌کند.
ابزار مرورگر در این محیط مرورگر متصل نداشت؛ بازبینی بصری با مرورگر واقعی همچنان لازم است.

## وکتور — نمونه‌کار شمارهٔ ۱

وکتور در `/demos/vector/` یک استودیوی تعاملی با مدل‌های لباس ارائه‌شده در پوشهٔ
`models/` است: هودی DG100024 در دو ترکیب رنگ CORE استخوانی و DRIFT زرشکی، و کاپشن
پلار W-Jacket 70 با نام SHELL. سطح لباس، چین‌ها، UV و نقشه‌های نرمال از همان فایل‌ها
می‌آیند. محیط، نوشته‌های سه‌بعدی، رنگ‌بندی و نشان وکتور در همین پروژه آماده می‌شوند.
مدل‌ها و تصاویر برند مرجع از پوشهٔ عمومی سایت کنار گذاشته شده‌اند.

ورودی‌ها `models/Blender.zip`، `models/OBJ.zip` و `models/Jacket+70_obj.zip` هستند؛
فایل Cinema 4D نسخهٔ جایگزین همان هودی است و تصاویر Picture.zip فقط مرجع ظاهری‌اند.
نام Digital Fashionwear در Read_Me هودی آمده است؛ سازندهٔ کاپشن در فایل‌های ارائه‌شده
ذکر نشده. منبع و هش آرشیوها و خروجی‌ها در
`public/demos/vector/assets/collection/ATTRIBUTION.json` ثبت می‌شود. برای این منابع
مجوز عمومی یا انتساب تألیف هندسه به وکتور ادعا نمی‌شود.

برای بازسازی، Blender 4.5 را با `VECTOR_BLENDER_BIN` معرفی و
`node scripts/render-vector-assets.mjs` را اجرا کنید. این دستور ورودی‌ها را بدون تغییر
باز می‌کند، بافت‌های رنگ را شخصی‌سازی می‌کند و `scripts/prepare-vector-models.py` را
برای تبدیل GLB و رندر Cycles اجرا می‌کند. سطح لباس بازسازی یا دوباره شبیه‌سازی نمی‌شود؛
نقشه‌های نرمال ۴K در منبع قابل ویرایش حفظ می‌شوند؛ خروجی وب از نقشه‌های ۲K و
فشرده‌سازی Draco استفاده می‌کند تا حافظه و زمان دریافت محدود بماند. حالت `--draft` سه نمای سریع برای بررسی
رنگ و فرم می‌سازد. `--convert-only` تصاویر رندرشده و ثبت منابع را به‌روز می‌کند.
بیلد معمولی به Blender یا پوشهٔ models نیاز ندارد.

GLB همراه بافت‌های PBR در `assets/collection/` قرار دارد و فایل قابل ویرایش Blender در
`design/vector/vector-collection.blend` ذخیره می‌شود. تصاویر محصول، پوستر جایگزین و
کمپین از همان هندسهٔ نمایش زنده رندر می‌شوند؛ عکس واقعی یا اسکرین‌شات مرورگر نیستند.
نماهای نزدیک در `assets/img/core-closeup.webp`، `drift-closeup.webp` و
`shell-closeup.webp` برای بازبینی جزئیات موجودند. تصاویر سه تیشرت فروشگاه به تصاویر
بدون برند پیشین برگشته‌اند و مدل سه‌بعدی این نمایشگاه نیستند.

روشنایی محیط، نور اصلی و سایه‌ها در نمایش زنده به متریال لباس شکل می‌دهند. اسکرول از
استودیو به چرخش کامل لباس و سپس چیدمان نهایی کالکشن می‌رود. موسیقی و کنترل خاموش/روشن
موجود حفظ شده‌اند و پخش به انتخاب کاربر است.

در نمای کالکشن، SHELL در مرکز و دو هودی هم‌شکل CORE و DRIFT در دو طرف قرار دارند؛
ترتیب دکمه‌ها و حرکت موبایل با همین چیدمان هماهنگ است. نمایش زنده و رندرها از تبدیل رنگ
Khronos PBR Neutral استفاده می‌کنند. هنگام خروجی glTF، وزن بازتاب مخملی پارچه در رنگ
sheen ضرب می‌شود، چون صادرکنندهٔ Blender 4.5 این وزن را منتقل نمی‌کند؛ در نتیجه لایهٔ
سفید با شدت کامل جای بازتاب ملایم پارچه را نمی‌گیرد.

مسیرهای `#studio/core`، `#studio/drift` و `#studio/shell` به محصولات هودی CORE، هودی
DRIFT و کاپشن SHELL وصل‌اند؛ مسیرهای قدیمی نیز به این کالکشن‌ها هدایت می‌شوند.
فروشگاه، علاقه‌مندی، انتخاب رنگ و سایز و سبد خرید حفظ شده‌اند. مدل استودیو رنگ پایهٔ
معرفی‌شده را نشان می‌دهد. سفارش و پرداخت نمایشی‌اند.

رندر در تب غیرفعال، خارج از دید و زیر پنجره‌های فروشگاه متوقف می‌شود؛ حالت کاهش حرکت،
بازیابی WebGL و آزادسازی منابع پشتیبانی می‌شوند. آزمون‌ها فایل‌های GLB را باز می‌کنند و
هویت منابع، نقشه‌های PBR، انتخاب با پرتو، اسکرول، تداخل پاسخ‌ها، آزادسازی منابع و جریان
خرید را می‌سنجند. آزمون‌های رندرکنندهٔ جایگزین، کیفیت تصویری GPU یا FPS مرورگر را اثبات
نمی‌کنند.

### رگال کالکشن تازهٔ وکتور

زیر استودیوی سه لباس اصلی، بخش `#rail` شش لباس تازهٔ PULSE، VOLT، GRID، COVE، NOMAD و
DUNE را روی یک رگال فلزی نشان می‌دهد. دو هودی، دو کاپشن و دو اورشرت به فروشگاه اضافه
شده‌اند و تعداد کل محصولات ۲۱ است. محصولات قبلی و شناسه‌های سبد خریدشان حفظ شده‌اند.

`public/demos/vector/rack.js` انتخاب، پیش‌نمایش، حرکت آویز، مرور با صفحه‌کلید و حرکت
افقی لمس را کنترل می‌کند. تصاویر روبه‌رو و کنار با ابزار داخلی `image_gen` ساخته
شده‌اند؛ نماهای کنار از تصویر روبه‌روی همان لباس به‌عنوان مرجع استفاده می‌کنند.
دستورهای ساخت در `design/vector/rail-images.json` و انتساب هر خروجی در فهرست دارایی‌های
وکتور ثبت می‌شوند. خروجی‌های WebP شفاف، محلی و با اندازهٔ ۱۰۲۴ در ۱۲۸۰ هستند.

ساختار رگال و آویزها با CSS و SVG ساخته شده و برای لباس‌های تازه مدل سه‌بعدی اضافه
نمی‌شود. تصاویر نزدیک محدودهٔ دید بارگیری می‌شوند؛ حرکت در حالت کاهش حرکت، تب
غیرفعال، بیرون محدودهٔ دید و زیر پنجرهٔ فروشگاه متوقف می‌شود. ورود به روایت استودیو
رگال را پنهان و بازگشت به خانه دوباره آن را نمایش می‌دهد. خرید از رگال به همان پنجرهٔ
انتخاب رنگ و سایز متصل است؛ هر لباس تازه فقط در رنگی که تصویرش را دارد عرضه می‌شود.

آزمون‌های رگال در `scripts/tests/vector.test.mjs` انتخاب شش محصول، اتصال خرید، حفظ سبد
قبلی و فوکوس، کلیدهای جهت‌نما، تفاوت حرکت افقی و عمودی لمس، بارگیری هنگام نزدیک‌شدن
و توقف حرکت را بررسی می‌کنند. این آزمون‌های DOM کیفیت بصری مرورگر یا FPS را اثبات
نمی‌کنند.
