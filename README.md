# نمونه‌کده | گالری نمونه‌کارهای فرانت‌اند فارسی

این مخزن یک وب‌سایت گالری است که **چهار وب‌سایت مستقل و کامل** را معرفی می‌کند. هر کارت در گالری
شما را به یک سایت واقعی با طراحی، محتوا، تصاویر و تعامل‌های خودش می‌برد — مجموعه‌ای از
اسکرین‌شات نیست.

همه‌ی رابط‌ها فارسی و راست‌به‌چپ‌اند و در رابط عمومی، هیچ پیوند یا آیکون گیت‌هاب وجود ندارد.

## فناوری‌ها

| بخش | ابزار |
| --- | --- |
| گالری اصلی | React 18 + TypeScript + Vite 5 |
| دموها | HTML + CSS + JavaScript (بدون فریم‌ورک، بدون وابستگی) |
| فونت | Vazirmatn (متغیر، woff2) — در گالری از طریق پکیج npm، در هر دمو به‌صورت فایل محلی |
| تصاویر | فایل‌های محلی WebP داخل مخزن |
| هاست | Cloudflare Pages (اتصال به گیت‌هاب، طرح رایگان) |

## ساختار پوشه‌ها

```
.
├── index.html                  # صفحه‌ی گالری (lang=fa dir=rtl)
├── src/
│   ├── App.tsx
│   ├── data/projects.ts        # ★ ثبت متمرکز پروژه‌ها
│   ├── lib/fa.ts               # یکسان‌سازی متن فارسی برای جست‌وجو
│   ├── components/             # هدر، هیرو، گالری، کارت، حالت خالی، درباره، فوتر
│   └── styles/gallery.css
├── public/                     # هرچه اینجا باشد عیناً به dist کپی می‌شود
│   ├── favicon.svg
│   ├── 404.html                # صفحه‌ی ۴۰۴ فارسی Cloudflare Pages
│   ├── images/previews/        # تصویر پیش‌نمایش هر دمو (۱۲۰۰×۸۰۰ WebP)
│   └── demos/
│       ├── fashion/            # آینه — خانه‌ی مد و استایل
│       ├── sports/             # پیکان — باشگاه ورزشی و تناسب اندام
│       ├── cars/               # ماشین‌نما — نمایشگاه خودرو
│       └── store/              # لوازم — فروشگاه سبک زندگی
└── scripts/
    ├── postbuild.mjs           # بررسی خروجی build (بخشی از npm run build)
    ├── check-site.mjs          # دروازه‌ی یکپارچگی: rtl/fa، تصاویر، پیوندها، attribution
    ├── fetch-images.mjs        # دانلود تصاویر از Wikimedia Commons
    ├── sync-images.mjs         # ساخت دوباره‌ی پیش‌نمایش‌ها از تصویر hero هر دمو
    ├── image-manifest.mjs      # فهرست تصویرهای پروژه (منبع + مقصد)
    └── lib/commons.mjs         # کلاینت ساده‌ی API مشترک
```

## فرمان‌ها

| فرمان | کار |
| --- | --- |
| `npm run dev` | گالری و دموها روی `http://localhost:5173` |
| `npm run build` | `tsc --noEmit` + `vite build` + `postbuild.mjs` |
| `npm run preview` | سرو کردن `dist` روی `http://localhost:4173` |
| `npm run typecheck` | فقط بررسی تایپ‌ها |
| `npm run check:site` | بررسی یکپارچگی محتوا و تصاویر (۴ دمو + گالری) |
| `npm run sync:images` | تولید دوباره‌ی `public/images/previews/*.webp` از hero هر دمو |
| `npm run search:images` | جست‌وجوی گزینه‌های تصویر در Commons |
| `npm run fetch:images` | دانلود و ساخت تصویرهای منیفست |

## نصب و اجرای محلی

```bash
npm install

```

نشانی‌های محلی:

| صفحه | نشانی |
| --- | --- |
| گالری | `http://localhost:5173/` |
| مد و پوشاک | `http://localhost:5173/demos/fashion/` |
| ورزش و تناسب اندام | `http://localhost:5173/demos/sports/` |
| خودرو | `http://localhost:5173/demos/cars/` |
| فروشگاه | `http://localhost:5173/demos/store/` |

چهار دمو فایل‌های ایستا داخل `public/` هستند و مستقل از راکت کار می‌کنند؛ هر کدام را می‌توان
مستقیم در مرورگر باز کرد.

## بیلد و پیش‌نمایش خروجی

```bash
npm run build      # tsc --noEmit && vite build && بررسی ساختار
npm run preview    # serving dist روی http://localhost:4173
```

خروجی:

```
dist/
├── index.html
├── assets/
├── images/previews/*.webp
└── demos/{fashion,sports,cars,store}/index.html + assets/
```

اسکریپت `scripts/postbuild.mjs` بعد از هر build این‌ها را کنترل می‌کند: وجود `index.html` هر چهار
دمو، `lang="fa"` و `dir="rtl"` در آن‌ها، نبود پیوند گیت‌هاب، نبود نشانی تصویر بیرونی، و وجود
تصویرهای پیش‌نمایش. اگر موردی نباشد، build با موفقیت تمام می‌شود؛ در غیر این صورت با کد خطا
خارج می‌شود.

## جست‌وجوی فارسی

جست‌وجو در `src/lib/fa.ts` یکسان‌سازی می‌کند و بعد تطبیق می‌دهد:

- `ي` عربی ⇄ `ی` فارسی، `ك` ⇄ `ک`، `ى` ⇄ `ی`، `ة` ⇄ `ه`
- حذف نیم‌فاصله (`U+200C`)، تطویل (`U+0640`) و اعراب
- یکسان‌سازی فاصله‌های یونیکد (از جمله NBSP) و حذف فاصله‌های اضافه
- ارقام فارسی/عربی ⇄ لاتین، و حروف لاتین به حروف کوچک

جست‌وجوی چندکلمه‌ای AND است (همه‌ی واژه‌ها باید پیدا شوند، بدون وابستگی به ترتیب) و روی
عنوان، توضیح، دسته‌بندی، واژه‌های کلیدی، امکانات و فناوری‌های هر پروژه اعمال می‌شود. فیلتر
دسته‌بندی و جست‌وجو با هم کار می‌کنند. متن اصلی دست‌نخورده نمایش داده می‌شود.

## افزودن دمو پنجم

۱. پوشه بسازید: `public/demos/<id>/` و داخل آن `index.html`، `styles.css`، `app.js` و
   `assets/` (تصاویر، فونت و …). مسیرهای تصویر را نسبی بنویسید (`./assets/img/x.webp`) تا در
   مسیر تودرتو `/demos/<id>/` درست کار کند.
۲. تصویر پیش‌نمایش گالری را با ابعاد ۱۲۰۰×۸۰۰ در `public/images/previews/<id>.webp` بگذارید.
۳. یک عضو به آرایه‌ی `projects` در `src/data/projects.ts` اضافه کنید (همان `id`، عنوان،
   توضیح، `category`، `preview`، `url: '/demos/<id>/'`، `technologies`، `keywords`،
   `highlights`، `accent`). فهرست دسته‌بندی‌ها خودکار از همین داده ساخته می‌شود.
۴. `npm run build` را اجرا کنید تا بررسی‌های ساختاری هم اجرا شوند.
۵. Push کنید؛ Cloudflare Pages با اتصال گیت‌هاب خودش دوباره deploy می‌کند.

کامپوننت‌های گالری داده‌محورند؛ برای دمو جدید نیازی به بازنویسی `App.tsx` یا کارت‌ها نیست.

## استفاده از بیلد استاتیک React/Vue در یک دمو

هر دمو فقط یک پوشه‌ی ایستا در `public/demos/<id>/` است؛ می‌توانید خروجی بیلد یک فریم‌ورک دیگر
را آنجا بگذارید:

```bash
cd ../my-vue-demo
npm run build -- --base=./          # یا در vite.config: base: './'
rm -rf ../demo/public/demos/my-vue-demo/assets
cp -r dist/* ../demo/public/demos/my-vue-demo/
```

نکته‌ها: مسیر assetها باید نسبی باشد (`base: './'`)، فایل `index.html` بیلد‌شده جای فایل
دستی را می‌گیرد، و اگر از React Router استفاده می‌کنید `HashRouter` بگیرید یا یک `_redirects`
اختصاصی برای همان دمو اضافه کنید تا مسیر دمو با روت گالری جایگزین نشود.

## تصاویر و اعتبار منبع

- همه‌ی تصویرها فایل‌های محلی داخل مخزن‌اند: `public/demos/<id>/assets/img/*.webp` برای دموها و
  `public/images/previews/*.webp` برای پیش‌نمایش گالری. بعد از deploy هیچ درخواستی به سرور
  تصویر بیرونی زده نمی‌شود.
- منبع تصویرها **Wikimedia Commons** است (لایسنس‌های CC0 / CC BY / CC BY-SA / مالکیت عمومی).
  برای هر تصویر، عنوان فایل، نام اثر‌گر و لایسنس در `public/demos/<id>/assets/ATTRIBUTION.json`
  ثبت شده و فهرست کامل با منبع در `public/images/ATTRIBUTION.json` جمع بسته می‌شود.
- چرا Unsplash/Pexels؟ این‌ها منبع ترجیحی طرح اولیه بودند، ولی شبکه‌ی این ماشین فقط به
  `upload.wikimedia.org`، `commons.wikimedia.org`، `registry.npmjs.org` و چند میزبان محدود پاسخ
  می‌دهد؛ `images.unsplash.com`، `images.pexels.com`، `cdn.pixabay.com` و `picsum.photos` مسدودند.
  برای همین همه‌ی تصویرها از Commons گرفته شده‌اند و **تک‌تک آن‌ها با چشم بررسی شده‌اند** تا سوژه‌ی
  هر کارت با تصویر همان کارت یکی باشد.

ابزار دانلود:

```bash
node scripts/fetch-images.mjs search "چراغ مطالعه"      # گزینه‌یابی
node scripts/fetch-images.mjs build                     # دانلود طبق image-manifest.mjs
```

اسکریپت با `sharp` تصویر را resize می‌کند، به WebP با کیفیت ۸۰ تبدیل می‌کند، فرمت خروجی را
اعتبارسنجی می‌کند و اطلاعات لایسنس را در فایل attribution می‌نویسد.

## استقرار روی Cloudflare Pages

1. مخزن را به Cloudflare Pages وصل کنید (**Workers & Pages → Create → Pages → Connect to Git**).
2. تنظیمات پروژه:

| تنظیم | مقدار |
| --- | --- |
| Framework preset | `None` (یا Vite) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | `/` (ریشه‌ی مخزن) |
| Node.js version (Environment variables) | `NODE_VERSION = 20` |

3. Deploy را بزنید. چون دموها فایل‌های واقعی داخل `dist/demos/<id>/index.html` هستند، نشانی‌های
   `/demos/fashion/`، `/demos/sports/`، `/demos/cars/` و `/demos/store/` بدون هیچ قانون rewrite
   باز می‌شوند. **عمداً هیچ `_redirects` سراسری مثل `/* /index.html 200` اضافه نکنید**؛ آن مسیر
   دموها را با گالری جایگزین می‌کند. صفحه‌ی `public/404.html` برای مسیرهای اشتباه کافی است.
4. برای اطمینان از کش صحیح assetها می‌توانید `public/_headers` را اضافه کنید (اختیاری):

```
/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

هاست رایگان Pages برای این سایت کافی است (سایت کاملاً ایستا، بدون backend، دیتابیس یا API key).

## قراردادهای داخل دموها

- **قاعده‌ی `[hidden]`:** هر `styles.css` درست بعد از `box-sizing` این خط را دارد:
  `[hidden]{display:none !important}`. بدون آن، `display:flex` روی درایور سبد، مودال یا دکمه‌ی
  پاک‌کردن جست‌وجو، قواعد مرورگر را می‌پوشاند و المان از همان بار اول صفحه دیده می‌شود.
- **لحن متن‌ها:** بازدیدکننده در نقش مشتری است، نه توسعه‌دهنده. پس متن‌ها به «شما» خطاب
  می‌کنند، توضیح معماری نمی‌دهند و تنها یک بار — کنار فرم یا سبد — صریحاً می‌گویند صفحه
  نمونه‌ی نمایشی است. واژه‌های فنی فقط در `keywords` بی‌نمایش `projects.ts` می‌آیند.
- **آمار با محتوا یکی باشد:** شمارنده‌های هیرو و بخش «پیکان در یک نگاه» باید با تعداد واقعی
  کارت‌ها بخواند (باشگاه ۶ رشته، نمایشگاه ۱۰ خودرو). عدد قلابی سریع‌ترین راه بی‌اعتمادی است.
- **تصویر = همان سوژه:** تصویر هر کارت/محصول باید موضوع همان کارت باشد؛ این با چشم بررسی
  می‌شود، نه با اندازه‌ی فایل.

## آنچه عملاً بررسی شد

هر مورد در مرورگر واقعی (دسکتاپ ۱۴۴۰ و موبایل ۳۹۰) آزمایش شده است:

- گالری: جست‌وجو با یکسان‌سازی (`ي/ی`، `ك/ک`، `ى`، اعراب، تطویل، نیم‌فاصله، ارقام فارسی/عربی،
  NBSP)، جست‌وجوی چندواژه‌ای بدون وابستگی به ترتیب، کار هم‌زمان فیلتر دسته و جست‌وجو، حالت خالی
  و دکمه‌ی بازگشت آن، منوی موبایل، نبود سرریز افقی.
- مد: فیلتر فصل، لایت‌باکس (کلیک، پیکان‌ها، Esc، `alt` معنادار)، فرم عضویت و پیام‌های خطا.
- باشگاه: فیلتر رشته‌ها، تب‌های روز هفته، دکمه‌ی اطلاع‌رسانی، فرم ثبت‌نام (اعتبارسنجی و موفق).
- خودرو: جست‌وجو + فیلتر کلاس + مرتب‌سازی با هم، پنجره‌ی جزئیات و تعویض تصویر، سقف سه‌تایی
  مقایسه و جدول مقایسه، فرم مشاوره.
- فروشگاه: سبد با `localStorage`، حذف/تغییر تعداد، تسویه‌حساب با اعتبارسنجی کد پستی، جست‌وجو،
  فیلتر دسته، مرتب‌سازی، نمای سریع، درایور سبد و Esc.
- همه‌ی صفحه‌ها: `lang="fa" dir="rtl"`، فونت محلی Vazirmatn، نبود هر پیوند یا آیکون گیت‌هاب،
  نبود تصویر بیرونی، نبود خطای کنسول.

`npm run check:site` هم همین موارد ساختاری را در هر build دوباره کنترل می‌کند.

## عیب‌یابی

| مشکل | علت و راه‌حل |
| --- | --- |
| `/demos/cars/` خطای ۴۰۴ می‌دهد یا گالری را نشان می‌دهد | فایل `dist/demos/cars/index.html` تولید نشده؛ مطمئن شوید دمو داخل `public/demos/…` است و `_redirects` سراسری اضافه نکرده‌اید. `npm run build` خروجی را کنترل می‌کند. |
| تصویر در دمو نمی‌آید | مسیر نسبی را با `./assets/...` بنویسید، نه `/assets/...`؛ فایل را با `ls dist/demos/<id>/assets/img` بررسی کنید. |
| فایل تصویر HTML یا ۰ بایت است | دانلود شکسته؛ `node scripts/fetch-images.mjs build` دوباره اجرا کنید و اندازه/فرمت را با `sharp metadata` بررسی کنید. |
| فونت فارسی نمی‌آید | فایل woff2 در `assets/fonts` باشد و `@font-face` مسیر نسبی درست داشته باشد. |
| چیدمان روی موبایل افقی اسکرول می‌کند | `overflow-x: clip` روی body و بررسی عرض جدول مقایسه/کارت‌ها؛ از `min-width` بزرگ روی المان‌های داخل flex استفاده نکنید. |
| جست‌وجوی فارسی نتیجه نمی‌دهد | املای کلیدواژه را با شکل `ي/ی` و `ك/ک` امتحان کنید؛ یکسان‌سازی در `src/lib/fa.ts` است و روی همه‌ی فیلدها اعمال می‌شود. |
| سبد خرید فروشگاه پاک می‌شود | کلید `localStorage` برابر `lavazem-cart-v1` است؛ در حالت Incognito یا بعد از `Clear site data` مقدار اولیه برمی‌گردد. |
| درایور سبد/مودال از همان اول صفحه باز است | قاعده‌ی `[hidden]{display:none !important}` از آن فایل CSS حذف شده؛ دوباره درست‌اش کنید. |

## مستندات توسعه‌دهنده

این README بخشی از مخزن است، نه بخشی از وب‌سایت عمومی. گالری و چهار دمو هیچ راهنمای
توسعه‌دهنده یا پیوند مخزن به بازدیدکننده نشان نمی‌دهند.
